## 1. 主研究问题 (RQ1)

**在 10~15 篇 RAG 论文构成的小规模知识库上,Dense Retrieval、Hybrid Retrieval 与 Hybrid+Reranker 三种检索配置,对检索质量与生成质量分别有何差异?**

拆分为两个可独立测量的子问题:

| 子问题 | 对应指标 | 回答的问题 |
|--------|---------|-----------|
| RQ1a 检索质量 | Hit@K、MRR | 正确的证据片段有没有被捞出来? |
| RQ1b 生成质量 | Faithfulness、引用正确率、拒答率 | 答案有没有忠实于证据、引用对不对、无证据时是否拒答? |

> **关键设计**:RQ1b 不能只看"答对的百分比"。引用正确率是北极星指标,详见 §3。

## 2. 附加问题

### RQ2 — 切块比较(正式实验)

**固定 Token 切块(512)与章节感知切块,哪一种更适合学术论文 RAG?**

- 定位:第二个正式实验矩阵。
- 理由(用户):切块影响应该较大;且"章节正确才算引用正确"这一标准,天然依赖切块是否保留章节信息。
- 前提:章节边界必须能可靠识别(优先 PDF 解析,失败时人工校对)。

### RQ3 — Top-K(健壮性抽查)

**Top-K 从 5 增至 8,引用正确率是否一定提升?**

- 定位:降级为健壮性抽查(主实验旁多跑 2~3 组),不单独做完整矩阵。
- 理由(用户):Top-K 是参数调优,不是结构差异。

> 分工逻辑:按控制变量法,切块与 Top-K 的结论都依赖检索方法先被固定 → 检索方法(RQ1)是地基,RQ2/RQ3 站在其上。

## 3. 核心价值观(决定指标怎么测)

用户明确的选择,是全部评估设计的锚点:

1. **引用正确率是北极星指标。** 理由:"大模型答得顺溜可能是幻觉" → 一个答案可信,首先因为引用正确。
2. **引用正确的标准 = 论文 + 章节 两层都对。** 仅论文对不算正确。
3. **无证据时应拒答。** "拒答"是系统的正确行为,不是缺陷。

由此推出生成质量必须拆成三件事,不能合并成一个"准确率":

- **忠实度**:答案有没有照着证据说;
- **引用正确率**:引用的论文、章节对不对(双层标准);
- **拒答率**:无证据时是否如实说不知道(进一步区分真拒答/误拒答,见 §5)。

## 4. 方法锁定原则(控制变量)

RQ1 三组实验要归因于"用哪个检索器"这一个变量,其余环节全部冻结:

| 必须冻结的环节 | 当前设定 |
|--------------|---------|
| 切块方式 | 固定 Token,size=512,overlap=80(对齐 `configs/dense.yaml` 与 `plan_20days.md` Day 7;Day 5 冻结时最终确认) |
| Embedding 模型 | `BAAI/bge-m3` |
| 生成模型 | `gpt-4o-mini`,temperature=0.2 |
| 提示词模板 | 只根据上下文回答;无证据拒答;引用对应真实 Chunk ID |
| 引用解析逻辑 | 返回论文 + 章节 + Chunk 原文 |
| 评估集 | 同一套,人工确认,不随实验改动 |

> 章节号应**随 Chunk 由检索器原样带回**,而非生成时让大模型"猜"——否则测的不是检索能力,而是模型猜章节的运气。二者测的是完全不同的事。

## 5. 实验设计要点

### 5.1 评估集标注(区分拒答类型)

每题标注 `answerable: true/false`,把"拒答率"拆成:

- **真拒答**(知识库无相关证据 → 系统拒答)= 正确行为;
- **误拒答**(知识库有证据但检索没捞到 → 系统拒答)= 检索失败,不是好行为。

未拆分前,单一"拒答率 20%"无法判断是该拒的拒了,还是该答的被误杀。

### 5.2 神谕检索消融(归因:检索 vs 生成)

判断指标差异究竟来自检索还是生成,加一组**神谕检索(oracle retrieval)**:

- 不跑检索器,直接把标注好的标准答案 Chunk 喂给生成器 → 得到"检索完美时的生成天花板"。
- 真实检索的生成结果 < 神谕检索 → 差距是**检索失败**造成的;
- 神谕检索本身分数也不高 → 问题出在**生成**或评估集标注。

### 5.3 展示层价值主张

系统展示可核查的证据块(论文、章节、Chunk 原文、检索分数),让用户"看到"可信度、减少额外核查负担。评估应验证这个承诺:检索正确性 + 引用正确性 + 拒答行为,三者都要覆盖。

## 7. 主要风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| R1 确认偏误 | 用户对"混合更好"有先验预期,分析时可能无意识偏向支持性结果 | 每个结论强制补一句"如果结果相反我如何解释";novelty-audit 把关 |
| R2 RRF 未必赢 Dense | 小知识库上 Hybrid 融合可能引入噪音,不保证优于 Dense | 如实报告;把"混合没赢"也作为可发表的负结果 |
| R3 章节边界解析失败 | PDF 章节号格式五花八门,解析失败率高 | 优先解析 + 必要时人工校对;解析不出的论文不硬凑 |
| R4 人工评估一致性 | 40~60 题人工判断引用是否正确,标准可能前后漂移 | 双层标准书面化;评估脚本与标注版本可追溯 |
| R5 指标打架 | 检索好但生成引用错,难以归因 | 神谕检索消融(§5.2)强行拆分 |
